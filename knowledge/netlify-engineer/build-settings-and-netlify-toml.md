# Build settings and netlify.toml

Sources:
- https://docs.netlify.com/build/configure-builds/overview.md
- https://docs.netlify.com/build/configure-builds/file-based-configuration.md
- https://docs.netlify.com/build/configure-builds/ignore-builds.md

## Definitions (build overview)
- **Base directory:** "directory where Netlify checks for dependency management files... installs dependencies, and runs your build command... If not set, the base directory defaults to the root of the repository." (Here: repo root.)
- **Build command:** "The build command runs in the Bash shell." (Here: `python scripts/build_analysis.py`.)
- **Publish directory:** "directory that contains the deploy-ready HTML files and assets generated by the build... relative to the base directory." **"Only files in the publish directory are deployed."** (Here: `site`.) So `nltk_layer.py` and `nltk_data` must be **copied into `site/`** by the build.
- **Functions directory:** default `netlify/functions`. We create none.
- "The configuration file settings override build settings specified in the UI."

## netlify.toml (from the official sample)
```toml
"$schema" = "https://open-api.netlify.com/netlify.schema.json"   # lets editors/agents validate the file
[build]
  base = "project/"         # optional
  publish = "build-output/"
  command = "echo 'default context'"
[context.production]        # deploys from the production branch
  command = "make publish"
  environment = { NODE_VERSION = "14.15.3" }
[context.deploy-preview]    # deploys from pull/merge requests
  publish = "dist/"
[context.deploy-preview.environment]
  NOT_PRIVATE_ITEM = "not so secret"
[context.branch-deploy]     # other branches
  command = "echo branch"
```
- "Settings for the [build] key are global and are applied to all deploy contexts unless overridden by a context-specific setting."
- The docs advise keeping sensitive values out of the repo: "we recommend using the Netlify UI for sensitive values." This project has no secrets.

### Project netlify.toml
```toml
"$schema" = "https://open-api.netlify.com/netlify.schema.json"
[build]
  command = "python scripts/build_analysis.py"
  publish = "site"
[build.environment]
  PYTHON_VERSION = "3.12"
  NLTK_DATA = "/opt/build/repo/nltk_data"
[[headers]]
  for = "/data/*"
  [headers.values]
    Cache-Control = "public, max-age=3600"
[[headers]]
  for = "/nltk_data/*"
  [headers.values]
    Cache-Control = "public, max-age=604800"
```
`/opt/build/repo` is the usual checkout path on Netlify's build machines. Confirm it in the first deploy log, or set `NLTK_DATA` from Python relative to the script instead.

## Ignore builds (saves time and credits)
- "Netlify attempts to ignore builds when they're not required." Override with `[build] ignore = "<bash command>"`.
- "An exit code of `1` indicates the contents have changed and the build process continues as usual. An exit code of `0` indicates that there are no changes and the build should stop."
- "If the command references a separate file, the file path must start with `./`." It doesn't cancel builds triggered by build hooks.
- Example for this repo, skipping builds when only `docs/`, `knowledge/` or `.claude/` changed:
  `ignore = "git diff --quiet $CACHED_COMMIT_REF $COMMIT_REF -- . ':(exclude)docs' ':(exclude)knowledge' ':(exclude).claude'"`
